# Self-Healing CI/CD Pipeline

> **Generative AI for AIOps** — A multi-agent system for autonomous diagnosis and repair of CI pipeline failures, with progressive escalation and RAG-based episodic memory.

This repository contains the implementation and experimental evaluation for the Master's thesis:

## Overview

The system autonomously detects CI failures triggered by GitHub Actions, classifies the error category, applies a progressive multi-attempt fix strategy, and opens a Pull Request with the proposed solution. Human intervention is only required for PR review and merge — the system never merges autonomously.

**Key results** on a 60-error synthetic benchmark:

| Model                 | Success Rate | Router F1 | Avg Latency |
| --------------------- | ------------ | --------- | ----------- |
| Claude Haiku          | **91.67%**   | 98.33%    | 46.98s      |
| GPT-4o                | 85.00%       | 98.33%    | 45.54s      |
| Llama 3.3 70B (Groq)  | 85.00%       | 91.53%    | 43.91s      |
| Llama 3.1 8B (Ollama) | 60.00%       | 75.56%    | 111.97s     |
| Mistral 7B (Ollama)   | 55.00%       | 83.62%    | 68.47s      |

## Architecture

```
GitHub Actions failure
        │
        ▼ webhook (HMAC-SHA256)
┌───────────────┐
│  FastAPI       │  POST /webhook/github
│  Webhook       │  Background task (Fire-and-Forget)
└───────┬───────┘
        │
        ▼
┌───────────────┐
│  Router Agent │  LLM classification → {category, confidence, reasoning}
└───────┬───────┘
        │
   ┌────┴─────────────┐
   ▼         ▼        ▼
Dependency  Test   Config
 Agent     Agent   Agent
   └────┬─────────────┘
        │
        ▼
┌───────────────┐    ┌─────────────────────┐
│ Fix Executor  │◄───│ Episodic Memory      │
│               │    │ (ChromaDB + RAG)     │
│ T1: conservative   └─────────────────────┘
│ T2: contextual
│ T3: RAG few-shot
└───────┬───────┘
        │
   CI green?
   ┌────┴────┐
   ▼         ▼
Create PR  Retry / Escalate
```

### Four Original Contributions

1. **Multi-Agent Event-Driven Architecture for Self-Healing CI** — Nine functional components orchestrated via a LangGraph stateful graph automate the full healing cycle asynchronously: from webhook reception through error classification, fix verification on an isolated branch, and structured Pull Request generation. The Human-in-the-Loop paradigm ensures the system operates in assisted mode, with the final merge decision delegated to the human operator.

2. **Progressive Escalation Strategy with Three Attempts of Increasing Aggressiveness** — Each attempt applies a qualitatively distinct prompt engineering strategy: a conservative fix at attempt 1, a contextual fix incorporating the previous failure history at attempt 2, and a RAG-assisted fix with few-shot examples from episodic memory at attempt 3.

3. **RAG-Based Episodic Memory with ChromaDB Persistence** — Every completed cycle — whether successful or escalated — is persisted in a vector database with semantic embedding. At the third attempt, specialized agents query the memory to retrieve the top-3 most similar past episodes, injected into the prompt as additional context. Episodes generated by Claude Haiku produce fixes at the third attempt even for different models in subsequent runs, realising cross-model knowledge transfer.

4. **Empirical Benchmark across Five LLM Models, Proprietary and Open-Source, on the Self-Healing CI Task** — The benchmark covers Claude Haiku, GPT-4o, Llama 3.3 70B (via Groq API), Llama 3.1 8B and Mistral 7B (both via Ollama locally), evaluated on a structured dataset of 60 CI errors across three categories and three difficulty levels.

## Setup

### Prerequisites

- Python 3.10+
- A GitHub repository with Actions enabled
- At least one LLM provider API key

### Installation

```bash
git clone https://github.com/EdoardoMaxia/ci-selfhealing-lab.git
cd ci-selfhealing-lab
python -m venv .venv

# Windows
.venv\Scripts\Activate.ps1

# macOS/Linux
source .venv/bin/activate

pip install -r project_requirements.txt
```

### Configuration

Copy `.env.example` to `.env` and fill in your credentials:

```env
# GitHub
GITHUB_TOKEN=ghp_...
GITHUB_REPO=EdoardoMaxia/ci-selfhealing-lab
GITHUB_WEBHOOK_SECRET=your_secret

# LLM Provider (anthropic | openai | groq | ollama)
LLM_PROVIDER=anthropic

# API Keys
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...         # also used for embeddings
GROQ_API_KEY=gsk_...

# Ollama (local inference)
OLLAMA_MODEL=llama3.1:8b      # or mistral:7b
```

## Running the System

### Webhook mode (production-like)

Start the FastAPI server and expose it via ngrok:

```bash
# Terminal 1 — start webhook server
python -m agent.pipeline.trigger

# Terminal 2 — expose to GitHub
ngrok http 8000
```

Then configure the ngrok URL as a webhook in your GitHub repository:
- **Settings → Webhooks → Add webhook**
- Payload URL: `https://<ngrok-id>.ngrok.io/webhook/github`
- Content type: `application/json`
- Secret: value from `GITHUB_WEBHOOK_SECRET`
- Events: **Workflow runs**

### Manual invocation

```python
from dotenv import load_dotenv
load_dotenv()

from agent.graph import app

result = app.invoke({
    "ci_logs": "<paste CI log here>",
    "ci_job_name": "Run Tests",
    "ci_conclusion": "failure",
    "commit_sha": "abc1234",
    "repo_name": "EdoardoMaxia/ci-selfhealing-lab",
    "git_diff": "",
    "repo_path": ".",
    "attempt_number": 1,
    "attempts_history": [],
})

print(result["final_status"])   # "fixed" or "escalated"
print(result["pr_url"])
```

### Running agent tests locally

```bash
pytest agent/tests/ -v
```

## Benchmark

The `experiments/` directory contains the full evaluation pipeline.

### Run benchmark

```bash
# Full run — no episodic memory (baseline)
python experiments/benchmark.py --provider anthropic --no-memory

# With episodic memory (ablation study)
python experiments/benchmark.py --provider anthropic --clean-memory

# Specific provider / model
python experiments/benchmark.py --provider groq --no-memory
python experiments/benchmark.py --provider ollama --ollama-model llama3.1:8b --no-memory

# Quick test (5 errors, no CI)
python experiments/benchmark.py --provider anthropic --dry-run --limit 5
```

### Generate figures

```bash
python experiments/analysis.py
# Outputs to experiments/figures/ — PDF (LaTeX-ready) + PNG
```

### Benchmark flags

| Flag             | Description                                            |
| ---------------- | ------------------------------------------------------ |
| `--provider`     | `anthropic` \| `openai` \| `groq` \| `ollama` \| `all` |
| `--ollama-model` | `llama3.1:8b` \| `mistral:7b`                          |
| `--category`     | `dependency` \| `test` \| `config` \| `all`            |
| `--difficulty`   | `easy` \| `medium` \| `hard` \| `all`                  |
| `--no-memory`    | Disable ChromaDB saving (baseline condition)           |
| `--clean-memory` | Wipe ChromaDB before run                               |
| `--dry-run`      | Router only, no real CI (implies `--no-memory`)        |
| `--limit N`      | Process only first N errors                            |

## Experimental Results

### Ablation Study — Episodic Memory Impact

| Model         | SR without memory | SR with memory | Δ          |
| ------------- | ----------------- | -------------- | ---------- |
| Claude Haiku  | 91.66%            | 91.66%         | = 0.00pp   |
| GPT-4o        | 85.00%            | 93.33%         | ▲ +8.33pp  |
| Llama 3.3 70B | 85.00%            | 86.66%         | ▲ +1.66pp  |
| Llama 3.1 8B  | 60.00%            | 73.33%         | ▲ +13.33pp |
| Mistral 7B    | 55.00%            | 53.33%         | ▼ −1.66pp  |

The +13.33pp improvement for Llama 3.1 8B is the largest observed delta and emerges from cross-model knowledge transfer: episodes generated by Claude Haiku improve the performance of a weaker open-source model via RAG few-shot injection at attempt 3.

### Attempt Distribution (without memory)

| Model         | Fix T1         | Fix T2       | Fix T3       | Escalation     |
| ------------- | -------------- | ------------ | ------------ | -------------- |
| Claude Haiku  | 53/60 (88.33%) | 1/60 (1.67%) | 1/60 (1.67%) | 5/60 (8.33%)   |
| GPT-4o        | 47/60 (78.33%) | 4/60 (6.67%) | 0/60 (0.00%) | 9/60 (15.00%)  |
| Llama 3.3 70B | 50/60 (83.33%) | 1/60 (1.67%) | 0/60 (0.00%) | 9/60 (15.00%)  |
| Llama 3.1 8B  | 34/60 (56.67%) | 2/60 (3.33%) | 0/60 (0.00%) | 24/60 (40.00%) |
| Mistral 7B    | 31/60 (51.67%) | 2/60 (3.33%) | 0/60 (0.00%) | 27/60 (45.00%) |

Fix T3 = 0% for all models without memory. T3 activates only with episodic memory enabled.

## Design Patterns

| Pattern                  | Implementation                                       |
| ------------------------ | ---------------------------------------------------- |
| Observer / HTTP Callback | GitHub webhook → FastAPI                             |
| Finite State Machine     | LangGraph 9-node directed graph                      |
| Strategy (GoF)           | `get_llm()` — switchable provider via `LLM_PROVIDER` |
| RAG                      | ChromaDB + cosine similarity retrieval at attempt 3  |
| Human-in-the-Loop        | System proposes PR; engineer reviews and merges      |
| Fire-and-Forget          | FastAPI `BackgroundTasks` for async CI processing    |
| Separation of Concerns   | Agents modify files; Fix Executor handles GitHub API |

## Resetting Files After Benchmark

The benchmark modifies `requirements.txt`, `tests/test_calculator.py` and `.github/workflows/ci.yml` to inject errors. To restore the repository to its clean state:

```bash
git checkout HEAD -- requirements.txt
git checkout HEAD -- tests/test_calculator.py
git checkout HEAD -- .github/workflows/ci.yml
```

Or restore everything at once:

```bash
git checkout HEAD -- .
```
